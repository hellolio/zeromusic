## 二、覆盖范围

- 引擎抽象：`AudioEngine.equalizer` 可空契约；不支持平台返回 null，业务零改动降级。
- 偏好持久化：`equalizerEnabled` / `equalizerGains` 往返保真；空库读默认值；损坏 JSON / 长度不匹配回退。
- 控制器：三态（不支持 / 未就绪 / 就绪）、偏好→引擎单路径镜像、就绪后 clamp + pad/truncate 应用、
  预设按 log(中心频率) 插值、重置、dispose / 引擎替换守卫。
- 设置页 UI：行值（开/关/不支持）、弹层三态、开关联动引擎并落盘、频段滑杆、预设 chips、重置。
- 启动链路：App 启动即应用已持久化的均衡器设置（经 AudioController 保活）。
- **不覆盖**：Android 真机频段数 / dB 范围 / 音效实际听感（写入开发心得人工验证清单）。

## 三、前置条件

- 数据：内置 `FakeDataLayer`（widget 测试不触达 drift 与真实平台插件）。
- 环境：`wrapApp` 注入 `FakeAudioEngine(equalizer: FakeEqualizer(...))` + `InMemoryPreferencesStore`；
  纯 Dart 测试用 `ProviderContainer` 直读 `equalizerControllerProvider`。
- `FakeEqualizer` 默认 5 段（60/230/910/3600/14000Hz）±15dB，`autoReady` 控制参数就绪时机。

## 五、用例明细（与上表编号一一对应）

### TC-EQ-01：不支持平台降级展示
- **前置条件**：`FakeAudioEngine()`（equalizer 默认 null）。
- **操作步骤**：
  1. pump 应用，切到设置页；
  2. 查看均衡器行；点击该行打开弹层。
- **预期结果**：行值为 `Not supported`；弹层仅标题 + 不支持说明文案，无开关、无滑杆、无预设。
- **异常/边界**：iOS/macOS/Windows/Linux 真机均走此分支。
- **实测结果**：☑ 通过

### TC-EQ-02：未就绪可开关、提示先播放
- **前置条件**：`FakeEqualizer(autoReady: false)`（模拟引擎尚未激活）。
- **操作步骤**：设置页打开均衡器弹层；拨动开关。
- **预期结果**：弹层显示开关 + `Start playback to adjust bands`；拨开后偏好 `equalizerEnabled=true` 落盘、引擎 `enabled=true`、行值变 `On`；仍不渲染滑杆。
- **异常/边界**：就绪前 gains 不得触达 band（对象尚不存在）。
- **实测结果**：☑ 通过

### TC-EQ-03：就绪后渲染滑杆并可调
- **前置条件**：`FakeEqualizer()`（autoReady，5 段 ±15dB）。
- **操作步骤**：打开弹层；拖第 1 频段滑杆。
- **预期结果**：渲染 5 条滑杆（各带频率标签与 dB 值）+ 6 预设 + 重置；拖动后偏好 `equalizerGains[0]` 变化、引擎 band0 `setGain` 收到同值（clamp 后）。
- **异常/边界**：拖到头/尾不超过 min/max；enabled=false 时滑杆区不渲染。
- **实测结果**：☑ 通过

### TC-EQ-04：预设一键应用
- **前置条件**：就绪。
- **操作步骤**：点 `Rock` chip。
- **预期结果**：偏好 `equalizerGains` == Rock 曲线（5 段时原值）；引擎各 band 同步；各滑杆跳到对应位置。
- **实测结果**：☑ 通过

### TC-EQ-05：重置为平直
- **前置条件**：就绪且已应用过非零增益。
- **操作步骤**：点 `Reset`。
- **预期结果**：偏好 gains 全 0；引擎各 band 归 0。
- **实测结果**：☑ 通过

### TC-EQ-06：启动即应用已持久化设置
- **前置条件**：`InMemoryPreferencesStore(AppPreferences(equalizerEnabled: true, equalizerGains: [1,2,3,4,5]))`。
- **操作步骤**：pump 应用（不打开弹层）。
- **预期结果**：引擎 `enabled=true`、各 band 增益 == [1,2,3,4,5]（AudioController 保活 EqualizerController）。
- **实测结果**：☑ 通过

### TC-EQ-07：gains 长度不匹配 pad/truncate
- **前置条件**：纯 Dart 容器；分别预置 3 段、7 段 gains（设备 5 段）。
- **预期结果**：3 段 → band3/4 补 0；7 段 → 仅前 5 生效；均无越界异常。
- **实测结果**：☑ 通过

### TC-EQ-08：超范围增益 clamp
- **前置条件**：预置 gains [100, -100]（范围 ±15）。
- **预期结果**：band0=15、band1=-15。
- **实测结果**：☑ 通过

### TC-EQ-09：损坏 gains JSON 回退默认
- **前置条件**：`SharedPreferences.setMockInitialValues({'prefs.equalizer.gains': '{broken'})`。
- **预期结果**：`load()` 返回 `equalizerGains == []`，不抛错。
- **实测结果**：☑ 通过

### TC-EQ-10：SharedPreferencesStore 往返
- **前置条件**：setMockInitialValues 空。
- **操作步骤**：save（enabled=true + gains [1.5,-2.0]）→ load。
- **预期结果**：字段保真；空库 enabled=false、gains=[]。
- **实测结果**：☑ 通过

### TC-EQ-11：就绪前开关缓冲、就绪后补应用
- **前置条件**：autoReady:false；预置 enabled=true + gains。
- **操作步骤**：read provider → `completeParameters()`。
- **预期结果**：就绪前 `enabled` 已镜像到引擎（激活时会带上）；gains 未触达 band；就绪后 gains 补应用且 state.ready=true。
- **实测结果**：☑ 通过

### TC-EQ-12：provider dispose 后参数完成不炸
- **前置条件**：autoReady:false。
- **操作步骤**：read provider → container.dispose → completeParameters。
- **预期结果**：无未捕获异步异常（ref.mounted 守卫）。
- **实测结果**：☑ 通过

### TC-EQ-13：预设插值
- **前置条件**：—。
- **操作步骤**：`presetGains(Rock, …)` 各形态。
- **预期结果**：5 锚点频段 → 原曲线；[910] ≈ 中频锚点值；[30] = 首点（clamp）；段数 != 5 时按 log 频率插值、长度保持。
- **实测结果**：☑ 通过

### TC-EQ-14：行值单源
- **前置条件**：三种引擎形态（null / 未就绪 / 就绪+开）。
- **预期结果**：行值依次为 Not supported / Off / On，全部派生自 `equalizerControllerProvider`。
- **实测结果**：☑ 通过

### TC-EQ-15：设置页既有用例回归
- **前置条件**：默认。
- **预期结果**：TC-01 断言由 `Coming soon` 改为 `Not supported`（限定均衡器行内）；主题/语言/音量/背景效果用例不受影响。
- **实测结果**：☑ 通过

### TC-EQ-16：均衡器状态变化不得清空播放队列
- **前置条件**：纯 Dart 容器；`playQueue` 2 首、startIndex=1。
- **操作步骤**：
  1. `completeParameters()`（模拟 Android 首播后参数就绪）；
  2. 再 `setEnabled(true)`。
- **预期结果**：`audioControllerProvider` 的 queue 保持 2 首、currentIndex=1。
  `AudioController.build` 用 `ref.listen` 保活而非 `ref.watch`——watch 会让均衡器
  状态变化触发 AudioController 重建，build 返回常量初态把队列清空（Android 必现）。
- **实测结果**：☑ 通过（修复前回滚验证：改回 watch 本用例必红）

### TC-EQ-17：仅经 AudioController 保活即应用持久化设置
- **前置条件**：预置 enabled=true + gains；容器只 read `audioControllerProvider`。
- **预期结果**：FakeEqualizer 收到 enabled 与 gains。不得直接 read
  `equalizerControllerProvider`（否则保活行被删掉测试仍绿，测不到该链路）。
- **实测结果**：☑ 通过
