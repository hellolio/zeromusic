## 二、覆盖范围

覆盖：跨窗口消息编解码、行状态计算与推送节流、控制器开关编排（fake 窗口 API）、歌词条 UI 各状态与交互动画回调、几何纯函数（尺寸/默认位置/出屏钳制）、设置页「桌面」分组（仅桌面可见 + 开关联动 + 字号 + 恢复位置）。
不覆盖（留待桌面端手工验证）：真实 OS 级窗口的透明/置顶/不抢焦点/拖动/跨显示器表现（见第十一节手工清单）。

## 三、前置条件

- 可自动化：Flutter 测试环境（locale 默认英文）、`FakeAudioEngine`、内存偏好存储、内存假数据层、fake `LyricWindowApi`；widget 测试不触碰真实平台窗口。
- 手工：macOS / Windows / Linux 桌面端，若干带 LRC 歌词与无歌词曲目。

### TC-29～TC-32：ready 握手 / 复用刷新 / ✕ 悬停 / 高度自适应（缺陷修复回补）
- **实测结果**：☑ 通过（见 desktop_lyrics_test.dart / desktop_lyrics_bar_test.dart）
- TC-30 的子窗口侧行为依赖平台通道，无法在 widget 测试中覆盖，自动化部分验证「configure 携带最新 initialState」的契约；实际显示留手工清单复核。
- TC-32 通过拦截 window_manager / screen_retriever 通道验证 setBounds 参数：宽度=字号档位宽，高度=**固定两行**内容高度向上取整；行数 2→1 时高度不变（窗口恒定两行高度，空行占位）。高度应用经 `LyricWindowResizeGate` 去抖（150ms），断言前需推进时间窗口。

### TC-33～TC-36：悬停控制条（✕ 右上角 + 播放控制）
- **实测结果**：☑ 通过（见 desktop_lyrics_bar_test.dart）
- 控制条与 ✕ 常驻树内（透明度动画 + IgnorePointer 门控），布局尺寸不随悬停变化。
- 音量滑杆拖动中仅更新本地覆写值，`onChangeEnd` 才回传主窗口，避免跨窗口通道刷屏。

### TC-37～TC-39：播放态/音量跨窗口链路与 setSize 闸门
- **实测结果**：☑ 通过（见 desktop_lyrics_test.dart / lyric_window_resize_gate_test.dart）
- TC-38 的音量回传走主窗口偏好（默认音量，与播放页音量弹窗同源），引擎同步由 AudioController 的偏好监听完成。
- TC-39 崩溃回归护栏：帧回调内不再直接 setSize，闸门保证「去抖合并 + 单飞串行 + 定时器轮次应用」（坑 12）。

### TC-40～TC-41：控制条回传接线与独立置顶（缺陷修复回补）
- **实测结果**：☑ 通过（TC-40 见 desktop_lyrics_bar_test.dart；TC-41 手工验证）
- TC-40 修复：壳层 `lyric_bar_app.dart` 原先只接线了 onClose/onDragStart，四个控制回调悬空导致点击无反应；现补齐并通过拦截回传底层通道验证事件序列。
- TC-41 修复：歌词条窗口原生样式补 `.nonactivatingPanel`（borderless 只保证不成为 key 窗口，但点击仍会激活 app，AppKit arrangeInFront 会把主窗口带到最前）；置顶层级（floating）不变，主窗口与歌词条的置顶完全独立。
- TC-41 第四轮返工：`.nonactivatingPanel` 只对 NSPanel 子类生效，desktop_multi_window 创建的普通 NSWindow 上该样式位被 AppKit 忽略（坑 16）——现改为在原生层自建 NSPanel 并把 FlutterView 迁入，点击不再激活 app。自动化无法覆盖，留手工清单复核。

## 六、手工验证清单（桌面端）

- [ ] macOS：背景全透明（仅见文字与投影，无任何底色）、置顶于普通应用之上、无边框无阴影、不进 Dock、点击不抢焦点、主窗口最小化后仍滚动、跨 Space（全屏应用上方）显示。
- [ ] macOS：首次开启 → 歌词条**立即出现**（ready 握手后 show，修复前首开永不显示）；**重启不自动恢复**（启动强制归零），手动打开开关后立即出现。
- [ ] 关闭后再开启 → 歌词条显示当前行（修复前展示关闭前的陈旧行）。
- [ ] Windows：透明 + 置顶 + 不进任务栏；已知限制：点击会激活窗口（设置页提示）。
- [ ] Linux：有合成器时透明；无合成器降级不 crash。
- [ ] 平时只见歌词：无背景无控件；鼠标悬停 → 淡底浮现 + 右侧播放控制条（音量/上一曲/播放暂停/下一曲/✕），可拖拽可点击关闭；移开后全部隐藏。
- [ ] 悬停不要求先点击：app 未激活（主窗口被遮挡）时悬停歌词条控制条照常浮现/隐藏。
- [ ] 点击 Dock 图标：主窗口被唤出置前（歌词条开着也如此）；主窗口**最小化**后点 Dock 能解除最小化还原（deminiaturize）。
- [ ] 悬停控制条点击不触发拖拽；控制条不遮挡时点击歌词区可拖动；音量拖动松手后主窗口音量同步（播放页/迷你条一致）。
- [ ] 悬停控制条的音量/上一曲/播放暂停/下一曲**点击确实生效**（播放暂停/切歌/音量同步）。
- [ ] 点击歌词条（含按钮/拖拽）时，被遮挡的主窗口**不会**跳到最前；歌词条始终置顶，与主窗口置顶状态互不影响。
- [ ] 悬停控制条遮挡歌词行尾属预期（仅悬停时）；若希望看全歌词可移开鼠标。
- [ ] 拖动定位顺滑、重启恢复、拖出屏幕后重启拉回。
- [ ] 窗口高度恒定为两行歌词高度，不随行数变化跳动。
- [ ] 崩溃回归：开关桌面歌词 + 播放/切歌/行数变化 + 拖动窗口，长时间运行不再出现 Impeller `SetupRenderPass` 崩溃（帧内 setSize 已改经去抖闸门）。
- [ ] 开关/字号/恢复位置即时生效；开关关闭时设置页只剩一行；重启记忆。
- [ ] 主窗口关闭（退出应用）→ 歌词条随进程一并关闭。
