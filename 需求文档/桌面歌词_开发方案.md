# 桌面歌词 · 开发方案

> 关联需求：《08_桌面歌词.md》｜平台：仅桌面端（macOS / Windows / Linux）
> 状态：实现中 ｜ 本文按构架 §9 流程在编码前编写。

---

## 1. 总体思路

主窗口是**唯一事实源**（DB / AudioEngine / 歌词仓库 / 偏好），歌词条是一个**独立 Flutter 引擎的透明置顶小窗**（desktop_multi_window），**纯渲染、零业务**：只消费主窗口推送的「当前句 / 下一句」状态消息；✕ 与拖动位置经反向通道回传主窗口，偏好写回只发生在主窗口。

行计算**完全复用 02 播放页歌词链路**（`lyricsLinesProvider` + `activeLyricIndexProvider`），保证两处表现一致。

## 2. 依赖选型

| 依赖 | 用途 | 定稿说明 |
|------|------|----------|
| `desktop_multi_window` ^0.3.1 | 第二窗口（独立引擎）+ 跨窗口 `WindowMethodChannel` | 官方示例模式：`WindowController.create()` + `hiddenAtLaunch` |
| `window_manager` ^0.5.2 | 子窗口属性与操作（Win/Linux 透明、无边框、置顶、拖动、取位置） | 其 macOS 实现取 `registrar.view.window`，注册进子引擎后即控制子窗口 |
| `screen_retriever` ^0.2.2 | 取显示器可见区域，用于位置钳制 | window_manager 的配套包 |

## 3. 窗口形态（平台差异收敛）

| 能力 | macOS | Windows / Linux |
|------|-------|-----------------|
| 注册插件进子引擎 | `MainFlutterWindow.awakeFromNib` 里 `FlutterMultiWindowPlugin.setOnWindowCreatedCallback` | runner：`DesktopMultiWindowSetWindowCreatedCallback`（Win）/ `desktop_multi_window_plugin_set_window_created_callback`（Linux）里 `RegisterPlugins` |
| 透明 + 无边框 + 置顶 + 不抢焦点 + 不进 Dock/任务栏 + 跨 Space | AppDelegate 侧原生一次配置：`styleMask=[.borderless]`（borderless 默认不可成为 key → **点击不抢焦点**）+ `isOpaque=false, backgroundColor=.clear` + `level=.floating` + `collectionBehavior=[.canJoinAllSpaces, .fullScreenAuxiliary]` | Dart 侧 window_manager：`setBackgroundColor(transparent)` + `setTitleBarStyle(hidden)` + `setAlwaysOnTop(true)` + `setSkipTaskbar(true)` |
| 显示（不抢焦点） | 原生自定义通道 `zeromusic/lyric_window/orderFront`（`orderFront` 不激活；`window_show`/`windowManager.show()` 都会 `NSApp.activate`，弃用） | `windowManager.show()`（**已知降级**：显示/点击可能夺取焦点，设置页提示） |
| 拖动 | Flutter `Listener.onPointerDown` → `windowManager.startDragging()`（原生模态拖拽，不依赖 Flutter 手势键位） | 同左 |
| 隐藏/显示复用 | 窗口**只建一次**，开关切换走 `hide/show`（避免反复创建引擎造成引擎泄漏） | 同左 |

统一降级：Win/Linux 的「点击抢焦点」为已知平台限制 → 设置页开关下方辅助文案；Linux 无合成器时透明失效为系统级表现，不 crash。

## 4. 模块与文件

```text
lib/services/desktop_lyrics/
├── lyric_bar_messenger.dart        # 跨窗口契约：状态消息 / 回传事件 / 窗口配置 的编解码（纯 Dart）
├── lyric_window_api.dart           # 抽象接口 open/close/configure/pushState/events + provider 注入点
├── desktop_lyrics_controller.dart  # Riverpod Notifier：开关镜像偏好、行变化推送、✕/位置回写偏好
└── lyric_window_desktop.dart       # 桌面实现（desktop_multi_window）+ 几何纯函数（尺寸/默认位/钳制）
lib/ui/desktop_lyrics/
├── desktop_lyrics_bar.dart         # 歌词条 UI：纯渲染（两行 + ✕ + 悬停淡底 + 行切换动画）
└── lyric_bar_app.dart              # 子窗口入口：轻量 MaterialApp + 通道接线（零业务）
```

- 偏好扩展（`preferences_controller.dart`）：`desktopLyricsEnabled`（默认 false）、`desktopLyricsFontSize`（小/中/大，默认中）、`desktopLyricsOffset`（`Offset?`，null = 默认底部居中）。
- 本地化：`AppStrings` 基类 + 中/英/日 同步新增 11 条文案（桌面分组、开关、字号档位、恢复默认位置、未在播放、间奏、焦点限制提示等）。
- 设置页：新增「桌面」分组（**仅桌面断点可见**）——开关行 + 字号选择 + 恢复默认位置。
- `main.dart`：入口分支子窗口（`args[0] == 'multi_window'`）→ `runLyricBarWindow()`；根组件 watch 控制器保活。

## 5. 数据流

```text
主窗口 DesktopLyricsController（Notifer<bool>，state = 开关）
  ├─ watch preferencesProvider           → 开关/字号/位置变化：open / close / configure（幂等，窗口复用）
  ├─ listen desktopLyricsStateProvider   → 行变化/切歌才推送（消息 == 去重 = 节流，对齐构架 §5.3）
  │     （select 音频态 + 复用 lyricsLines/activeLyricIndex → LyricBarStateMessage）
  └─ listen LyricWindowApi.events        → ✕：偏好置关；拖动结束：偏好存位置（写回只在主窗口）
        ↓ WindowMethodChannel(push: 'zeromusic/lyric_bar/push'，单向)
歌词条窗口 LyricBarApp（纯渲染）
  ├─ 初始状态随窗口创建参数携带（无闪白），后续只消费推送
  ├─ ✕ → 回传 closed → 主窗口关偏好；兜底自隐藏
  └─ 拖动结束 → 回传 position → 主窗口存偏好
```

## 6. 动画（对齐构架 §5）

- 行切换：`AnimatedSwitcher`，入句自下淡入、出句上滑淡出，250ms ease-out，**可中断**；`MediaQuery.disableAnimations` 时时长归零直接替换。
- 悬停淡底：`AnimatedContainer` 160ms；✕ 悬停：透明度 + `AnimatedScale` ≤ 200ms。

## 7. 测试策略

- 纯 Dart：消息编解码、几何（尺寸/默认位/钳制）。
- 控制器（fake `LyricWindowApi` + FakeAudioEngine + 内存偏好/数据层）：启动恢复、开关开合、✕ 回写、位置回写、推送节流与内容（有词/无词/无曲目/切歌）。
- Widget：`DesktopLyricsBar` 各状态（正常行/间奏/无词/无曲目/最后一句）、✕ 与拖动回调、减弱动效；设置页桌面分组（移动端不可见/桌面可见/开关联动/字号/恢复位置）。
- widget 测试**不触碰真实窗口**：默认偏好关闭 + 测试用 fake API；真实平台行为留待桌面端手工验证。
