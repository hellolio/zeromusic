# 本地音乐播放器 · 项目整体构架

> 版本：v1.0 ｜ 日期：2026-08-15 ｜ 平台：iOS / Android / macOS / Windows / Linux
> 本文档是**项目总纲**，统一定义：功能范围、平台适配、UI 风格、动画规范、技术选型、模块分层、开发流程。
> 所有功能需求文档、测试用例、开发心得均以此为准。

## 1. 项目定位与核心理念

一款**本地音乐播放器**，同时附带**视频播放**能力。核心体验对标 Apple Music：

- **UI 偏 iOS**：毛玻璃、圆角、简洁元素、统一图标与排版。
- **流畅**：所有操作有丰富的、自然的动画（spring 弹性曲线、页面转场、手势联动）。
- **统一**：移动端与桌面端使用**同一套设计语言与组件**，视觉一致。
- **本地优先**：歌曲存于设备本地，无需联网即可播放。

## 3. 平台适配策略（核心，必须同时适配桌面端与移动端）

**铁律：一套代码、一套设计语言，但在导航布局与交互上按平台自适应（responsive）**，绝不能为某个平台单独做一套 UI。

### 3.1 布局差异 —— 响应式断点

| 维度 | 移动端（iOS/Android） | 桌面端（macOS/Win/Linux） |
|------|----------------------|--------------------------|
| 导航 | 底部 TabBar（3 项） | 左侧 NavigationRail（4 项，播放页也在此） |
| 迷你播放条 | 悬浮于 TabBar 上方、内容底部 | 悬浮于右下角 |
| 播放页入口 | 迷你条上滑/点按 | 左侧导航项 + 迷你条点按 |
| 断点 | 按可用宽度判断，推荐 `>= 840px`（横向）时切换为桌面布局 |

### 3.2 响应式实现

- 使用 `LayoutBuilder` + 断点（`enum DeviceType { mobile, desktop }`）在根部决定布局骨架。
- 提供统一封装 `AdaptiveScaffold`，内部根据类型渲染「TabBar + 迷你条」或「NavigationRail + 迷你条」。
- 内容区组件（列表、卡片、弹窗）保持跨平台一致，只在**容器/导航层**做分支。

### 3.3 交互差异适配

| 交互 | 移动端 | 桌面端 |
|------|--------|--------|
| 歌曲右键菜单 | 长按 / 点「⋯」三点按钮 | 鼠标右键 + 点「⋯」 |
| 悬停反馈 | 无（按下态 feedback） | hover 高亮、工具提示（tooltip） |
| 迷你条切歌 | 左右滑动 | 上一首/下一首按钮 + 滚轮 |
| 滚动 | 触摸拖拽 | 鼠标滚轮 + 滚动条 |

### 3.4 平台能力注意点

- **音频引擎**：各平台需统一 `just_audio` 或 `audioplayers`，桌面端需额外配置系统音频输出。
- **权限**：存储/蓝牙/WiFi/网络权限在各平台 `Info.plist`、AndroidManifest、macOS entitlements 分别声明。
- **文件选择**：桌面端用原生文件选择器，移动端用 `file_picker`/系统分享导入。

## 4. UI 风格规范（iOS 风，统一）

### 4.1 设计令牌（Design Tokens）

所有颜色、字体、间距、圆角一律通过集中定义使用，禁止硬编码。

```
主题：浅色 / 深色 两套，跟随系统 + 手动切换
令牌：
  color.background / color.backgroundElevated / color.accent
  color.textPrimary / color.textSecondary / color.surfaceBlur
  spacing.xs=4 / s=8 / m=16 / l=24 / xl=32
  radius.s=8 / m=12 / l=20 / pill=999
  font.size 各级标题/正文/说明
```

- 浅色：白/浅灰背景、黑字、accent 取 Apple 蓝 `#0A84FF`。
- 深色：近黑背景 `#000000/1F1F1F`、白字。
- 语义色：喜欢=红、歌词高亮=accent。

### 4.2 组件风格

- **毛玻璃**：使用 `BackdropFilter + ImageFilter.blur` 做导航栏、迷你条、弹窗背景。
- **圆角**：卡片/弹窗漩涡大圆角（≥12），按钮多用胶囊形。
- **图标**：统一 `CupertinoIcons`（iOS 风格），禁止混用材质图标。
- **动静**：默认开启系统动效；尊重系统"减弱动态效果"设置（`MediaQuery.disableAnimations`）。

### 4.3 统一组件库

在 `lib/ui/` 建内部组件库：`AppBar`、`SongTile`、`BottomSheet`、`MenuItem`、`MiniPlayer`、`CoverArt` 等，所有页面复用，保证统一。

## 5. 动画规范（丰富、流畅、简洁、统一）

> 目标：Apple 级 spring 手感。所有动画**不阻塞交互**、**可取消**、**方向明确**。

### 5.1 动效曲线

- 统一使用 **spring 弹性**：推荐 `Curves.easeOutCubic`（进出场）与 spring 物理模拟（`SpringSimulation`）用于手势回弹。
- 时长：进场 250–350ms，微交互 120–200ms，长动画 400ms 以内。

### 5.2 动效清单（统一实现）

| 场景 | 动效 |
|------|------|
| 页面/导航切换 | 横向滑动 + 透明度 + 微缩放（`SlideTransition`+`FadeTransition`） |
| 迷你条出现/隐藏 | 从底部 y 位移 + 淡入（`AnimatedSlide`） |
| 迷你条切歌 | 左右滑出/滑入，带动生成映 |
| 播放页进出 | 自下而上（上滑进入），背景毛玻璃过渡 |
| 播放/暂停 | 图标 `AnimatedSwitcher` 旋转/缩放切换 |
| **节拍变色背景** | `AnimatedContainer` 颜色插值 + 跟随音乐能量值（详见 02_播放页面） |
| 列表增删 | `AnimatedListView`/`AnimatedList` 行列展开收起 |

### 5.3 实现约束

- 优先 `ImplicitlyAnimatedWidget`（`AnimatedContainer`、`AnimatedSwitcher`、`AnimatedSlide`、`AnimatedOpacity`）。
- 复杂手势用 `AnimationController` + `PhysicsSimulation`，并统一封装在 `lib/anim/`。
- **禁止** `setState` 驱动逐帧色变阻塞 UI；节拍变色应基于音频能量采样，节流更新。

## 6. 技术选型

| 领域 | 方案 | 说明 |
|------|------|------|
| 音频引擎 | `just_audio`（跨平台统一） | iOS/Android/macOS/Win/Linux 均支持 |
| 视频播放 | `video_player` 或 `media_kit` | 桌面端 `media_kit`（libmpv）更稳 |
| 音频元数据/扫库 | `on_audio_query`（移动）/平台通道（桌面） | 统一抽象为 MediaRepository |
| 本地数据库 | `drift` 或 `sqflite + drift` | 元数据、喜欢、标签、播放统计 |
| 状态管理 | `Riverpod` | 统一、可测试 |
| 本地化 | `flutter_localizations` + `intl` | 中/英/日，默认中文 |
| 文件选择 | 移动 `file_picker` / 桌面原生对话框 | 导入页使用 |
| 主题/令牌 | 自建 ThemeExtension | 跨平台统一 |

> 所有平台特定实现都通过 repository/service 接口封装，业务层不感知平台。

## 7. 模块分层架构

```
lib/
├── main.dart                 # 入口：初始化、主题、本地化、根路由
├── core/                     # 跨页面通用
│   ├── theme/                # 设计令牌、主题扩展
│   ├── localization/         # 中/英/日 文案与切换
│   ├── platform/             # 响应式断点、平台能力判断
│   └── anim/                 # 统一动画曲线与组件
├── ui/
│   ├── scaffold/             # AdaptiveScaffold（TabBar / NavigationRail）
│   ├── components/           # 统一组件库（SongTile、BottomSheet…）
│   ├── mini_player/          # 全局迷你播放条
│   └── pages/                # 播放列表 / 播放页 / 导入 / 设置 / 视频
├── data/
│   ├── repository/           # 媒体库、喜欢、标签、播放记录
│   ├── database/             # drift 表结构
│   └── platform_media/       # 平台扫库通道
└── services/
    ├── audio/                # 播放引擎封装（AudioService 单例）
    ├── import/               # 云端/蓝牙/WiFi/Mac/Win 导入
    └── lyrcis/               # 歌词解析与同步
```

### 7.1 播放引擎（核心单例）

`AudioService` 全局单例，持有当前队列、当前曲目、播放状态、进度、能量值：

```
AudioService
 ├─ QueueController   # 播放队列管理（顺序/循环/随机、下一首）
 ├─ PlaybackController# 播放/暂停/seek、进度流、状态流
 ├─ EnergyAnalyzer    # 节拍/能量估算（驱动背景变色）
 └─ Notifier          # 向所有页面广播状态（迷你条、播放页、列表实时刷新）
```

**依赖方向**：UI → services/audio（监听状态）→ data（取元数据）。低层不依赖 UI。

## 9. 开发流程规范（重要）

> 每个功能必须严格按此流程，**测试通过才算完成**。

### 9.1 流程

```
1. 读需求       结合《整体构架》+ 对应功能《需求文档》，理解当前开发任务
2. 写开发方案    在需求文档所在模块说明实现思路、组件、服务、数据模型
3. 先写测试用例  按《模板_测试用例》在开发前编写（成果物，入库）
4. 开发          按构架分层与动画规范实现
5. 测试          运行全部相关测试，必须全部通过
6. 写开发心得    按《模板_开发心得》记录坑与解法（成果物，入库）
7. 完结归档      测试用例 + 开发心得 一并提交
```

### 9.2 验收（Definition of Done）

- [ ] 单元/组件测试全部通过（`flutter test`）
- [ ] `flutter analyze` 无新增错误
- [ ] 移动端 + 桌面端各自手工验证布局与交互
- [ ] 动画流畅、可取消、符合本节规范
- [ ] 测试用例与开发心得已归档

### 9.3 测试策略

- 状态/服务层：用纯 Dart 单元测试 + mock 平台。
- 组件层：`flutter_test` widget 测试，验证渲染、布局、动画初终态。
- 集成：`integration_test` 跑真实播放流（可跳过桌面音频硬件环境）。
- 平台差异：关键交互（右键、悬停、迷你条）抽成可复用的测试 helper。
