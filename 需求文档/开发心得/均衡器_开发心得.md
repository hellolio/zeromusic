## 二、功能实现概要

- 实现功能点：
  - 设置页均衡器行从「即将支持」占位升级为完整功能：开/关、6 预设（平直/流行/摇滚/爵士/古典/电子）、
    逐频段滑杆（频率标签 + dB 值 + 0.5dB 步进）、重置。
  - 三态降级：**不支持**（非 Android 平台）→ 仅说明文案；**未就绪**（引擎未激活=首次播放前）→
    开关可用 + 「开始播放后可调节」提示；**就绪** → 完整调节 UI。
  - 偏好持久化：`equalizerEnabled` + `equalizerGains`（JSON），启动即应用（AudioController 保活链路）。
  - 对齐真实设备：增益按设备段数 pad 0 / 截断、clamp 到设备 ±dB 范围；预设 5 点曲线按
    log(中心频率) 插值到实际段数。
- 核心组件/服务：
  - `services/audio/equalizer.dart`：`AudioEqualizer / EqualizerParameters / EqualizerBand` 抽象，
    业务零依赖 just_audio；`AudioEngine.equalizer` 可空契约。
  - `just_audio_engine.dart`：构造时按 `Platform.isAndroid` 门控创建 `AndroidEqualizer`，
    `_ensurePlayer` 经 `AudioPipeline` 注入（管线只能在创建播放器时挂上）。
  - `equalizer_controller.dart`：偏好为唯一事实源，方法只写偏好，`ref.listen(preferencesProvider)`
    单路径镜像引擎（与 AudioController 音量镜像同构）；`enabled` 立即应用，gains 就绪后统一补应用。
  - `equalizer_sheet.dart`：复用 `showCenterPopup` + `GlassOverlay`，每频段一行水平滑杆。
- 关键技术点：just_audio 0.10.6 仅 Android 提供均衡器（`AndroidEqualizer`），iOS/macOS/桌面无实现——
  按需求「交由引擎支持度」降级，不为不支持平台引入第三方 DSP 依赖。

## 三、遇到的问题与解决（坑）

### 坑 1：`ref.watch` 保活易变 provider → 播放队列被清空（评审抓出的 P0）
- **现象**：（预修复回滚验证）Android 首次播放后，迷你条突然消失、自动切歌失效、播放模式被重置。
- **原因分析**：为「启动即应用均衡器」在 `AudioController.build` 里写了
  `ref.watch(equalizerControllerProvider)`。Riverpod 3 中依赖方状态一变，watch 方即整体重建，
  且 **Notifier 重建会用 `build()` 返回值整体替换 state**——而 AudioController.build 返回
  `const PlaybackState()`（空队列）。均衡器参数就绪（首播激活后 `parameters` 完成）/
  播放中拨开关/拖滑杆，任何一次 EQ 状态变化都会把队列清空。200 例全绿却没拦住：纯 Dart EQ 测试
  不建 AudioController；widget 测试从不「边播放边改 EQ」；CI 非 Android 参数永不就绪。
- **解决过程**：怀疑者评审按 riverpod 源码（`ProviderElement._performRebuild` →
  `handleCreate` → `setValue(AsyncData(build()))`）逐步验证链路；改为
  `ref.listen(equalizerControllerProvider, (_, _) {})`（订阅即保活/提前实例化，不触发重建）。
- **最终方案**：listen 保活 + 新增 TC-EQ-16（playQueue 后触发参数就绪/开关，断言队列不变——
  改回 watch 必红，已回滚验证）与 TC-EQ-17（只 read audioControllerProvider，断言 EQ 设置经
  保活链路应用——直接 read EQ provider 会掩盖保活失效）。
- **经验**：**Notifier 的 build 不是「初始化」，是「状态工厂」**——对它 watch 任何易变 provider
  都是在给 state 装定时炸弹。保活用 listen/read，watch 只用于「状态确实该随之重置」的场景；
  且回归测试必须覆盖「保活链路本身」，否则实现被删测试仍绿。

### 坑 2：懒加载 provider 导致纯 Dart 测试「flush 空转」
- **现象**：控制器测试初版 13 例挂 10 例，`ready` 永远 false。
- **原因分析**：`ProviderContainer` 创建后什么都没读，`build()` 从未执行；
  `await Future.delayed(Duration.zero)` 只是在空转，`_loadParameters` 从未开始。
- **最终方案**：`pump()` 末尾 `container.read(equalizerControllerProvider)` 显式触发 build
  （等同 App 启动时 AudioController 保活），再 flush。
- **经验**：纯 Dart 容器里 provider 是严格懒加载的，「先建容器再等异步」什么都等不到。

### 坑 3：just_audio 均衡器的「激活时序」决定了三态设计
- **现象**：`AndroidEqualizer.parameters()` 只在引擎激活（首次 load/play）后完成；
  激活前 band 对象根本不存在，`setGain` 无的放矢。
- **解决过程**：读 just_audio 0.10.6 源码确认：`_activate` 时才 `androidEqualizerGetParameters`；
  `InitRequest` 会携带 effect 的 `enabled`（激活前 `setEnabled` 激活时生效）；
  `AndroidEqualizerBand.setGain` **自身不 clamp**，越界直达平台。
- **最终方案**：均衡器实例**构造即存在**（否则 Android 首播前 getter 为 null，「未就绪」态不可达）；
  `enabled` 立即应用、gains 等就绪后统一补应用并 clamp；完成回调带 `ref.mounted` + 引擎实例
  双重守卫（防 dispose 后写 state 抛错 / 换引擎后旧回调写脏 state）；**不加超时**——永不完成
  是设计内（未播放），加超时会把「未就绪」误报成「不支持」。
- **经验**：包装第三方能力前先把它的生命周期读穿（激活、恢复、重建三条路径），
  降级态与中间态往往是设计的主要工作量。

### 坑 4：垂直滑杆的手势竞技场冲突（方案阶段规避）
- **现象**：（评审预警）`RotatedBox` 旋转 Slider 做垂直滑杆时，本地水平拖拽 = 全局垂直拖拽，
  与弹层 `SingleChildScrollView` 的 VerticalDragGestureRecognizer 同场竞技，拖动可能变滚动。
- **最终方案**：改为每频段一行「频率标签 + 水平 Slider + dB 值」——无旋转、与纵向滚动方向正交、
  `tester.drag(Offset(dx,0))` 直接可测，440px 弹窗里 UX 也更自然。
- **经验**：弹层内容一旦可能滚动，内部手势控件的拖拽方向必须与滚动方向正交。

## 四、跨平台差异记录

| 平台 | 遇到的问题 | 解决方式 |
|------|-----------|----------|
| iOS | just_audio 无均衡器实现 | 引擎返回 `equalizer == null`，UI 降级「不支持」 |
| Android | 唯一支持平台；段数/±dB 设备相关；参数首播后才可读 | 三态 UI + pad/truncate/clamp + 构造即注入 AudioPipeline |
| macOS | 同 iOS（Darwin 无实现） | 降级「不支持」 |
| Windows | 无实现 | 降级「不支持」 |
| Linux | 无实现 | 降级「不支持」 |

## 五、动画实现要点

- 弹层复用 `showCenterPopup`（弹性缩放 + 淡入 + 背景模糊随转场渐变），无新增动画代码。
- 滑杆为 implicit 交互反馈（Slider 自身）；enabled 切换后滑杆区出现/消失用布局直切，
  弹层内避免重动画干扰拖动手势。
- 拖动滑杆每 tick 写偏好 + 镜像引擎：与音量滑杆同模式（仓库既有约定），未做节流；
  全频段 5 次 `setGain` 平台调用量级可忽略。

## 六、可复用经验 / 改进方向

- 沉淀模式：
  - **「偏好单源 + listen 单路径镜像」**：公共方法只写偏好（持久化），build 里
    `ref.listen(preferencesProvider)` 统一镜像引擎，杜绝「方法直写 + 监听回写」双路径漂移。
  - **异步回调双守卫**：`ref.mounted` + 绑定实例比对（`_boundEngine != engine`），
    防 dispose 后写 state / 旧实例回调写脏 state；回调内不碰 `ref`。
  - **三态能力降级**（不支持/未就绪/就绪）：平台能力接入的通用骨架。
  - `FakeEqualizer`（Completer 可控就绪时机）是测「异步就绪链路」的通用 fake 形态。
- 后续可优化项：
  - 偏好监听可按 eq 字段比对跳过无关变更（主题切换也会触发一次 setEnabled 镜像，幂等但冗余）。
  - `setBandGain` 可只写变动频段而非全量回写（当前与音量同模式，可接受）。
  - 若未来接入 media_kit 等引擎：实现一个 `implements AudioEngine` + 其均衡器包装即可，
    业务零改动（抽象层已就位）。
- **Android 真机人工验证清单**（自动化无法覆盖）：
  1. 不同机型频段数与 ±dB 范围读取正确（典型 5 段 ±15dB，部分机型不同）；
  2. 首次播放后弹层从「未就绪」自动转为滑杆 UI；
  3. 开关/预设/滑杆的实际听感与 bypass 对比；
  4. 杀进程重启后 EQ 设置自动恢复；
  5. 播放中拖滑杆无爆音/卡顿。
