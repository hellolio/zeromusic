# UI 微调 4 · 开发心得

> 功能：桌面迷你条按钮重排（歌词开关→音量→⏮→⏯→⏭）/ 歌词按钮图标对齐播放页 / 移动端滑动切歌改轮播式 1:1 跟手并消除重影。测试全部通过后编写。

## 踩坑与解法

### 1. 「重影」的根因：0.55× 滞后 peek 是刻意设计，但用户读作 bug
- **现象**：移动端迷你条左右滑动时歌名/歌手出现两份、滑动速度不同，像重影。
- **根因**：原实现是「后层 peek」——邻曲文本以 `_offset * 0.55` 滞后跟手、85% 透明度垫在当前文本后面，想营造层叠纵深感。但两块文本同时可见且速度不同，用户读作渲染缺陷。**设计意图 ≠ 用户感知**：小尺寸、高对比文本上，任何「不同速」都会被读成 bug，而不是层次。
- **解法**：改成轮播式（carousel）——邻曲文本摆在当前文本旁**一格文本区宽度**处（`offset + dir * W`），两块文本**同速 1:1**、全不透明度：左滑下一曲从右缘滑入，右滑上一曲从左缘滑入，完全跟手。同速之后「层次感」没了，但换来的直觉感（像翻页）才是用户要的。

### 2. 动画相位可以合并：「滑出→换曲→滑入」三步并一步
- 原相位机是 out（滑出 220）→ 切歌 → slideIn（新曲从对侧滑入回弹），两段动画共约 650ms。
- 轮播式下可以合并：滑出目标改为 `-dir * W`（一格宽度），当前文本滑出与邻曲归位**发生在同一相位**——动画结束时邻曲文本正好停在中点，此刻切歌 + 复位，视觉完全无缝（新曲文本已在中央，切歌只是换数据）。总时长 260ms，比原来快一倍多且无「二次入场」的割裂感。
- **要点**：合并后滑出曲线不能带过冲（`easeOutBack` 会让邻曲冲过中点再晃回），改用 `easeOutCubic`。**同一参数服务两个角色时，过冲只会对其中一个合理**。

### 3. 文本区宽度不要拍常数，用 LayoutBuilder 实测
- 原实现用固定常数（拖动上限 96 / 滑出距离 220），与真实文本区宽度（约 170，随屏宽/字号变化）无关，peek 位置全靠手感调。轮播式的邻曲初始位置必须在「恰好一个可视宽度」处（否则初始就露边或离得太远），只能实测：文本区外包 `LayoutBuilder`，把 `constraints.maxWidth` 存给手势与动画用（`_trackWidth`，首帧前用 240 兜底）。
- **教训**：跟手动画的「一步」应该等于可视宽度，而不是魔数；魔数在不同屏宽下都会露馅。

### 4. 图标换新时按「锚点」找引用，不要按「记忆」
- 歌词按钮图标从 `text_quote` 换成播放页同款 `doc_text`，引用点只有 mini_player 与其测试两处——全局搜图标名确认后一次改齐。图标名是测试断言的一部分（`find.byIcon`），**换图标 = 同时改断言**，漏一处测试直接红。

### 5. 既有手势测试是重构安全网
- 本轮改写了滑动切歌的核心状态机（删相位、改距离、改曲线），但阈值（56px/速度 800）、打断接管、回弹、减弱动效语义都未动——`mini_player_animation_test` 的「小幅回弹/切歌复位/连续滑动/动画中打断接管」四个用例零改动通过，直接证明行为兼容面没被破坏。**先想清楚「什么不该变」，让旧测试替你盯住它**。

## 回归保障

- 新增断言「拖动中两块文本中心距恒定」（`closeTo` 0.5px 容差），从机制上锁死「同速」，任何未来引入滞后的改动都会被这条断言拦下；
- 桌面按钮顺序用中心 x 坐标严格递增断言锁死，重排无需人眼校对。
