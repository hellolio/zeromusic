# 开发心得

> 来自一次 Flutter 播放列表功能的全量测试排查（视口过窄 / 模态遮罩拦截 / ListTile 断言崩溃等）。

**1. 测试环境就是一面照妖镜**

- Flutter 测试默认视口 800×600，很窄。水平列表第 6 个 chip（`Tags ▾`）中心在 x=856，**屏幕外**——`tester.tap` 会静默落空，只打日志不报错。排查技巧：用 `tester.getRect(finder)` 打印坐标，或直接 grep `"would not hit test"` 定位。
- 同理，默认高度只挂载了可见的 6 行，后面的断言全错。修法不是改断言，而是 `pumpPlaylist` 里统一把视口加高（800×1800），一屏内容全可见。

**2. 数据流问题先用 probe 定性，别急着改逻辑**

- 之前怀疑筛选面板拿不到 `tagsProvider` 或 repo 有问题，结果 probe 显示 `tagsProvider` 三次都正常——问题根本不在 state，而是 tap 根本没点上去。**先分清是"数据问题"还是"交互问题"**，省得白改一堆代码。

**3. Widget 测试的"外点关闭"要显式做**

- 标签选择器是多选面板，勾完不自动关。测试里直接去点下一个按钮，会被模态遮罩挡住。真实用户会"点外部关闭"，测试里就得 `tester.tapAt(const Offset(20, 20))` 模拟一次。**流程测试要走完真实用户的所有操作，包括关闭弹层。**

**4. Flutter 框架断言是有效讯号**

- `ListTile` 被 `ColoredBox` 包裹时喷漆不可见——这个 debug 断言虽然烦人，但指出了真实 UI bug：`GlassOverlay` 用 `Container(color:)` 当背景，把 `ListTile` 的涟漪效果全吃了。官网建议的修法 `Material(color:)` 一举解决了测试崩溃 + 视觉问题。**升级 Flutter 后跑全量测试，经常能"免费"抓到框架层面的问题。**

**5. 断言要挑确定性的写**

- `最近播放` 断言 `tiles.last.song.title == '演员'` 依赖空值排序，不稳；改成 `tiles.last.song.lastPlayedAt == null`（无播放记录排最后）就确定。**测试断言写"不变量"而不是"某一次运行结果"。**

## 核心一句话

**慢即是快**——先定数据没问题，再查坐标是不是打偏了，最后才碰逻辑和 UI 代码。
