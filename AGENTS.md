# AGENTS.md

Flutter app (Dart 3.13 / Flutter 3.47). Single-package, no monorepo.

## Commands
- `flutter pub get` — restore deps
- `flutter analyze` — lint/typecheck (lints only `lib/` and `test/`; platform dirs are excluded in `analysis_options.yaml`)
- `flutter test` — run tests (single test: `flutter test test/widget_test.dart`)
- `flutter run` — run app

## Project layout
UI framework skeleton is set up per `需求文档/整体构架.md`:

- `lib/core/theme/` — Design tokens (`app_tokens.dart`) + light/dark themes (`app_theme.dart`, `AppThemeExtension`).
- `lib/core/localization/` — 中/英/日 via `AppStrings`/`AppLanguage` (`app_strings.dart`, `strings_zh/en/ja.dart`, `localizations_delegate.dart`). Access via `context.strings`.
- `lib/core/platform/` — `DeviceType` + breakpoint (`AppBreakpoints.desktop` = 840).
- `lib/core/anim/` — unified curves (`app_curves.dart`) + page transition (`app_page_transitions.dart`).
- `lib/services/audio/` — **播放全部走抽象层**：业务代码只 import `audio_engine.dart`（`AudioEngine` 接口），实现文件为 `just_audio_engine.dart`（纯 just_audio 原生解码）+ `track.dart`；`audio_controller.dart`（Riverpod Notifier，编排队列并镜像引擎流）；`audio_engine_provider.dart` 是**换引擎的唯一注入点**（新建一个 `implements AudioEngine` 的实现替换即可，业务零改动）。`preferences_controller.dart`（theme/locale/motion）。
- `lib/ui/scaffold/adaptive_scaffold.dart` — responsive skeleton: mobile = bottom NavigationBar (播放列表/导入/设置) + swipeable PageView + mini player above; desktop = NavigationRail (4 items incl. 播放) + mini player bottom-right.
- `lib/ui/mini_player/` — global floating mini player capsule.
- `lib/ui/pages/` — blank pages for other AIs to fill: `playlist/`, `player/`, `import/`, `settings/`, `video/` (video not in nav yet).

## Gotchas
- `lib/core/localization/app_strings.dart`: do NOT use `context.strings` above `MaterialApp` (Localizations unavailable) — read `AppLanguage.fromLocale(prefs.locale).strings` instead.
- Mini player visibility: shown globally when `audioControllerProvider` has a `currentTrack` (hasTrack); hidden when the full player page is open — mobile hides it by pushing a full-screen route over it, desktop passes `hidden: _index == 3` (player nav item). Empty media library = hidden.
- Production has no demo/fake data and starts with an empty library (import real files to populate). Test-only fixtures live in `test/support/demo_fixtures.dart`.
- Playback is REAL: `AudioController` drives an `AudioEngine` (via `audioEngineProvider`). Player behavior (play/enqueue/toggle/next/previous/seek, auto-next on completion) lives in the controller state; engine streams mirror position/duration/playing into `PlaybackState`. Format support (`just_audio` native codecs) varies by platform — unsupported codecs surface through `errorStream` and the state stays consistent (paused).
- Mobile nav pages use a `PageView` (swipe to switch) synced with the `NavigationBar` via `_onPageChanged`/`_onNavSelected`; desktop uses `AppPageTransition`.
- `Track` (`lib/services/audio/track.dart`) carries `title/artist/album/duration/filePath/coverPath`; built from `Song` via `Track.fromSong`. The media library will keep extending it later.
- Mini player: mobile swipes left/right to change track (drag-follow + spring-back + slide-out/in), swipes up to open the player page; desktop has ⏮/▶/⏭ buttons + scroll-wheel switching + a fixed 320px-wide capsule (Positioned right/bottom gives unbounded width, so a fixed width is required).
- Widget tests must NOT touch real audio: `wrapApp()` in `test/helpers.dart` overrides `audioEngineProvider` with `FakeAudioEngine` (`test/support/fake_audio_engine.dart`) by default. To inject a custom engine, pass `audioEngine:` to `wrapApp` — do NOT re-override `audioEngineProvider` via the `overrides` list (duplicate-provider conflict).
- `.widget_preview/` is auto-generated by `flutter widget-preview` (gitignored). It is a separate nested Flutter package that depends on `zeromusic` via path. Do not hand-edit; it is regenerated.
- Test env locale defaults to English — widget tests locate nav destinations by icon, not text, to stay locale-independent.
- Test env vs real env are separated: widget tests (`test/widget_test.dart`, `test/playlist_page_test.dart`) run against an in-memory fake data layer (`test/support/fake_data_layer.dart` + `fakeDataLayerOverrides()` in `test/helpers.dart`) and never create/open/close a drift database. Drift's real behavior is covered by pure-Dart tests (`test/database_test.dart`, `test/repository_drift_test.dart`), where `await db.close()` in plain `test()`/`tearDown` is safe.
- Do NOT `await AppDatabase.close()` inside a `testWidgets` body after a page-switch `pumpAndSettle`: drift's `StreamQueryStore.close()` awaits fake timers, deadlocking the widget-test (fake-async) environment. Keep drift DB work out of widget tests entirely.
- Adding a new `AppStrings` getter requires updating `strings_zh/en/ja.dart` + the base class.
